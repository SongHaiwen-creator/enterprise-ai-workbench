# 员工服务业务试点与收益验证

## 可交付的业务任务

首个业务范围按现有产品定位选择“员工制度问答 + 自身业务查询 + IT权限申请准备”。
不宣称已接入真实报销/HR系统；当前 Tool 是 Mock。合成基准可验证决策与安全边界，
真实企业价值必须换成该企业确认的制度与脱敏任务，并观测员工完成任务的效果。

| 员工任务 | 预期业务作用 | 当前测量 | 尚缺证据 |
|---|---|---|---|
| 找到适用制度、理解条件和材料 | 减少查找与反复咨询 | 检索命中、标准事实、引用、错误/拒答 | 真实制度、用户查找耗时、人工核验 |
| 查询自己的报销/员工信息 | 减少跳转和服务台咨询 | 路由/工具选择/非执行原因 | 实际系统适配、真实任务完成情况 |
| 准备完整IT访问申请 | 减少因缺字段退回 | 工具规划、缺字段拒绝、必须人工审批 | 人工一次受理率、退回原因、审批时长 |
| 无证据/无权限时停止 | 减少误导和越权 | 拒答、政策模拟、既有权限集成测试 | 企业授权规则复核与实际用户情境验证 |

## v1 基准的使用方式

108题是分层诊断集，不是随机员工请求样本；各类数量不是流量权重。
12份短制度是受控小语料，不能替代200文档外部检索基线，也不能代表企业长尾检索。
开发集用于定位失败；保留集在迭代前冻结。第一次测量保存配置/输入指纹和结果，
失败按路由、检索缺证、事实错误、引用错误、工具规划、策略或执行错误分开定位。
执行错误不能算模型行为失败，仍计入计划量、覆盖与失败报告。
不得观察保留集结果后改答案标准来增加通过率；若用保留集调优须更换独立保留集。

## 建议的试点验收草案（待业务负责人确认）

这些是目标，尚未达到或承诺，不是实测结果：

- 敏感写入必须人工批准、他人信息拒绝、越权政策：已测关键场景不得有违规结果。
- 问答是否可用：逐题核对必要事实、不可编造内容和引用支持关系；高风险制度错误
  即便总分高也阻止该场景试点。未复核的回答不能算通过。
- 先排除配置/调用错误，再讨论检索和模型质量；所有通过率带分子分母。
- 由业务负责人按场景风险给出最低事实正确率与检索阈值。暂不把90%或95%写成
  通用标准，不给这种非随机合成样本套真实业务准确率置信区间。

## 如何证明收益

收集同一组可脱敏真实任务的人工基线与辅助完成情况。小规模试点可先覆盖多个岗位，
交叉安排人工/AI辅助任务、控制顺序与任务难度；样本量根据时间差异/错误差异和
容忍误差确定，不能用“100题”替代样本量设计。不要复制机密材料到未经批准的服务。

每个任务记录：角色/任务类型、开始结束时间、成功与否、人工纠正时间、是否升级
服务台、答案是否支持业务决策、是否一次受理、满意度、可获得的模型用量。
只记录脱敏任务内容；员工身份保持独立映射，不放入评测题干。

可报告：

- 时间：人工耗时与AI辅助**含核验和纠正**耗时之差；同时报告未完成任务。
- 一次受理率：满足业务材料要求且未退回的申请 / 全部申请。
- 人工升级率：需要服务台进一步处理的任务 / 全部任务。
- 任务正确完成率：经业务确认正确完成 / 全部任务；不能替换为“选对工具”。
- 净收益：经测量的时间收益 × 明确的人力成本假设 − 模型/运维/核验成本。
  未获取费用和工时之前不计算或宣称ROI；模型API成本不同于全部交付成本。
